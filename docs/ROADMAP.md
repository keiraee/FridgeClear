## 阶段 A：界面优化（当前集中）

目标：让用户在 PC 和手机上都能顺畅完成「看库存 → 看推荐 → 看菜谱 → 生成备餐」全流程；加载、空状态、错误提示风格统一。

### A1. 全局与导航

- [x] 统一全站 loading / empty / error 文案与样式（`loading-copy`、`empty-copy`、`error-copy`）
- [x] 顶部导航在移动端可折叠或底部 Tab 更易触达
- [x] 页面切换与按钮点击反馈（hover / active / disabled）一致
- [x] 检查登录态失效后的跳转与提示

### A2. 首页（Dashboard）

- [x] 接入库存推荐接口，展示匹配率
- [x] 菜谱卡片信息密度（星级、热量、时长、简介）
- [x] 无库存 / 无匹配结果时的引导（跳转添加库存、浏览全部菜谱）
- [x] 移动端 Hero + 库存状态卡片布局压缩
- [x] 「按一餐探索」按钮与分类筛选联动（而非仅跳转列表）

### A3. 菜谱列表与详情

- [x] 菜谱详情页（封面、食材、步骤、来源）
- [x] 列表分类筛选

- [x] 详情页步骤配图与统计标签
- [x] 列表页移动端：分类 chips 横向滚动、搜索框布局
- [x] 详情页移动端：Hero 单列、步骤图宽度、画廊网格
- [x] 无封面图的占位样式统一（与卡片一致）
- [x] 详情页「加入备餐」改为跳转备餐页并可选携带 recipeId（若简单可做）

### A4. 备餐计划（MealPlan）

### A5. 库存（Pantry）

- [x] 新增/编辑表单在手机上全宽、日期选择器易点

### A6. 管理端与其他

- [x] `AdminAiConfig` 表单在窄屏下的布局
- [x] 登录/注册页移动端间距与错误提示

### 阶段 A 完成标准

3. 前后端构建通过：`mvn compile` + `cd web && npm run build`。

> **背景：** 阶段 A 完成后，2026-08 又做了一轮细节打磨（commit `2a041c8` 等）。本节记录**已完成项**与**待办项**，供下次继续迭代时直接勾选。  
> **原则：** 不重复阶段 A 的大项；优先小改动、高体感；不做多语言（见「明确不做」）。

### F0. 已完成（2026-08-06）

- [x] 菜谱详情：收藏按钮、库存匹配率、加入备餐 toast、封面加载失败回退
- [x] 菜谱详情：无封面移动端 fallback 样式修复

- [x] 登录：受保护路由 `redirect` 回跳；全局确认弹窗（替换 `window.confirm`）
- [x] 导航：未登录搜索 toast 提示；`aria-current` / `aria-pressed` / Toast `aria-live`

- [ ] **备餐队列清空确认** — `MealPlan.vue`「清空」待安排队列前调用 `showConfirm`（与删除计划一致）
