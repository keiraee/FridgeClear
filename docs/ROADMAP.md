## 阶段 A：界面优化（当前集中）

目标：让用户在 PC 和手机上都能顺畅完成「看库存 → 看推荐 → 看菜谱 → 生成备餐」全流程；加载、空状态、错误提示风格统一。

### A1. 全局与导航

- [ ] 统一全站 loading / empty / error 文案与样式（`loading-copy`、`empty-copy`、`error-copy`）
- [ ] 顶部导航在移动端可折叠或底部 Tab 更易触达
- [ ] 页面切换与按钮点击反馈（hover / active / disabled）一致
- [ ] 检查登录态失效后的跳转与提示

### A2. 首页（Dashboard）

- [x] 接入库存推荐接口，展示匹配率
- [x] 菜谱卡片信息密度（星级、热量、时长、简介）
- [ ] 无库存 / 无匹配结果时的引导（跳转添加库存、浏览全部菜谱）
- [ ] 移动端 Hero + 库存状态卡片布局压缩
- [ ] 「按一餐探索」按钮与分类筛选联动（而非仅跳转列表）

### A3. 菜谱列表与详情

- [x] 菜谱详情页（封面、食材、步骤、来源）
- [x] 列表分类筛选
- [x] 卡片点击进详情
- [x] 详情页步骤配图与统计标签
- [ ] 列表页移动端：分类 chips 横向滚动、搜索框布局
- [ ] 详情页移动端：Hero 单列、步骤图宽度、画廊网格
- [ ] 无封面图的占位样式统一（与卡片一致）
- [ ] 详情页「加入备餐」改为跳转备餐页并可选携带 recipeId（若简单可做）

### A4. 备餐计划（MealPlan）

- [x] 计划项展示封面、点击进菜谱详情
- [x] 生成中进度条 / 阶段文案在窄屏下不挤压
- [x] 历史计划列表样式与空状态
- [x] 采购清单在移动端改为卡片列表（替代宽表格）
- [x] 计划项食材 chips 在小屏下单列展示

### A5. 库存（Pantry）

- [x] 表格在移动端改为卡片列表
- [x] 临期食材视觉强调（色条 / 角标）与首页数据一致
- [x] 新增/编辑表单在手机上全宽、日期选择器易点
- [x] 空库存引导文案与 CTA

### A6. 管理端与其他

- [ ] `AdminAiConfig` 表单在窄屏下的布局
- [ ] 登录/注册页移动端间距与错误提示

### 阶段 A 完成标准

1. 在 375px 宽视口下，首页、菜谱、详情、备餐、库存均可操作，无横向溢出。
2. 主要路径空状态均有明确下一步指引。
3. 前后端构建通过：`mvn compile` + `cd web && npm run build`。
